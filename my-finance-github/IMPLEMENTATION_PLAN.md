# План збірки

Після кожного кроку оновлювати PROGRESS.md і робити коміт українською. Після змін у файлах обліку запускати `uv run bean-check main.beancount`; крок завершено лише після перевірки без повідомлень. Вміст `data/` лише читати. Нових пакетів без дозволу не встановлювати.

## 1. Підготувати облік і категорії

**Зробити:** створити основу `main.beancount` з валютою PLN, відкриттям рахунків та початковими 4 500 PLN на 31 липня 2026 року через рахунок початкового капіталу. Створити порожній генерований файл операцій і підключити його. Узгодити `rules.csv` з вимогами: кафе та доставка — `Expenses:Кафе-І-Доставка`; додати Play як телефон, Rossmann як косметику й побутову хімію, Decathlon як спорт. Зберегти окремі продукти та пріоритет Bolt Food перед Bolt; позначити всі шість фіксованих витрат.

**Перевірити:** усі рахунки з правил відкриті; початкові гроші не зараховані в дохід; правила для Bolt Food і Bolt різні, Play — мобільний оператор. Запустити перевірку Beancount.

## 2. Імпортувати виписки

**Зробити:** створити `import.py`, який читає всі CSV з `data/` і правила, генерує `transactions.beancount` та зберігає порядок рядків банку. Використовувати дату завершення; повтори визначати за датою завершення, описом, сумою й залишком. Застосовувати перше правило без урахування регістру; невідомі витрати відносити до `Expenses:Без-Категорії`, надходження — до `Income:Інше`. Фіксовані операції позначати `#fixed`. Додати звірку залишків із випискою.

**Перевірити:** запустити `uv run python import.py` та перевірку Beancount. Звірити початковий і кінцевий залишки та проміжні залишки в порядку банку. Повторний імпорт має давати той самий результат; перевірити об’єднання виписок із повторними рядками на тимчасових копіях поза `data/`.

## 3. Підготувати щомісячні відповіді

**Зробити:** додати нативні директиви `query` для витрат за категоріями, доходу та заощаджень, фіксованих і керованих витрат за календарними місяцями. Розрахувати відсотки за PRD; нульовий знаменник показувати як «—». Неповний жовтень явно позначити, не прогнозувати.

**Перевірити:** виконати запити через `uv run bean-query` і перевірку Beancount. Зіставити місячні підсумки з випискою; сума категорій і сума фіксованих та керованих витрат мають збігатися. Перевірити приклад 2 000 / 9 800 = 20,4%, нульовий дохід і від’ємні заощадження.

## 4. Зробити звіт зручним для щомісячного використання

**Зробити:** підготувати локальний `report.html` із трьома відповідями за кожен місяць та позначкою неповного періоду. Додати в README короткі команди імпорту, перевірки, створення звіту й запуску Fava через `uv run fava main.beancount -p 5050`.

**Перевірити:** пройти весь шлях від CSV до звіту за інструкцією, звірити цифри зі збереженими запитами, відкрити звіт і Fava. Переконатися, що git ігнорує приватні та службові файли.

## Частина 2 — реалізація

1. Розділити імпорт Олі та Марка, зберегти банківські звірки, об’єднати кафе й доставку. Перевірити обидва обліки та незмінність загальних сум.
2. Додати SQLite для готівкових записів, похідні окремі файли й відновлення. Перевірити повторне надсилання, імпорт, перезапуск і відсутність впливу на банк.
3. Додати Flask: два логіни зі спільним доступом, власник, місяць, звіти та форма витрати. Перевірити CSRF, приховані прямі URL, cookies, HTTPS і помилки вводу.
4. Додати verify.py, тести та README для клону. База CSV має проходити; повна звірка має явно не проходити, доки не надано контрольні дані умови.
5. Після отримання правил Марка та еталона оновити категоризацію/еталон і виконати повну перевірку.
6. Після надання акаунтів підготувати публікацію PythonAnywhere, секрети, HTTPS, резервування та строк дії після 09.11.2026. Перевірити реальним телефоном. Не позначати цей етап виконаним без публічного URL і перевірки.
