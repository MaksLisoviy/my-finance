# Фінансовий трекер Олі та Марка

Python 3.12, Beancount 3, Flask. Обидва користувачі після входу бачать фінанси обох і можуть додавати готівкові витрати для кожного. Валюта — PLN.

## Запуск після клонування

1. Встановіть Python 3.12 та uv, клонуйте репозиторій і відкрийте його папку.
2. Виконайте `uv sync --locked`.
3. Обидві штучні виписки завдання включено в репозиторій: `data/statement.csv` (Оля) і `data/marko-statement.csv` (Марко). Окремо завантажувати їх не потрібно. Папка `data/` для програми лише для читання; справжні фінансові дані сюди не додавайте.
4. Виконайте `uv run python import.py`: створюються банківські операції, порожня база ручних витрат і повні обліки в `instance/`.
5. Виконайте `uv run python verify.py --baseline`. Очікується код 0, друк цифр обох власників, перевірка Beancount без повідомлень.

## Одна команда перевірки домашнього завдання

```bash
uv run python verify.py
```

Команда імпортує обидві виписки, перевіряє банківські залишки, відтворюваність імпорту, підсумки категорій, fixed + variable = усі витрати та запускає bean-check для банківського й повного обліку обох власників. Друкує фактичні й очікувані цифри Олі та Марка. Помилка або відсутній еталон умови означають ненульовий код завершення.

**Контрольні дані з умови поки не надані.** Тому повна команда зараз повертає код 1 після успішної перевірки бази CSV. Це не підтвердження здачі ДЗ. Доступна перевірка наявної бази:

```bash
uv run python verify.py --baseline
```

Після отримання умови створіть приватний `checks/assignment.json` за структурою `checks/baseline.json`, додайте `confirmed: true`, точне джерело `source`, а в кожному місяці обох власників — `income`, `expenses`, `saved`, `savings_percent` (null за нульового доходу), `fixed`, `variable`, `closing`, `count`, `categories`. Поле `categories` — об’єкт `{"Expenses:Продукти": "123.45", ...}` з усіма категоріями місяця. Очікувані значення беруться з умови; не копіюйте неперевірену базу замість неї. Інший шлях: `uv run python verify.py --expected /private/assignment.json`.

Банківський еталон перевіряється без доданих вручну витрат. Поточний облік із готівкою перевіряється окремо: ручні витрати закономірно змінюють підсумки.

## Вхід і локальний вебінтерфейс

Імена користувачів: `ola` та `marko`. Паролі задаєте ви. Для кожного створіть хеш:

```bash
uv run python password_hash.py
```

Введення приховане; результат — scrypt-хеш. Передайте хеші у змінні `OLA_PASSWORD_HASH` та `MARKO_PASSWORD_HASH`, а випадковий секрет щонайменше 32 символи — у `SECRET_KEY`. Створити секрет: `uv run python -c 'import secrets; print(secrets.token_urlsafe(48))'`. Не надсилайте секрети в чат і не комітьте їх. `.env.example` — лише перелік змінних, автоматичного завантаження `.env` немає. У shell беріть хеш у одинарні лапки, бо він містить `$`.

Після налаштування змінних у локальному терміналі:

```bash
FINANCE_LOCAL_HTTP=1 uv run flask --app app:create_app run --host 127.0.0.1 -p 5050
```

Відкрийте `http://127.0.0.1:5050`. Прапорець `FINANCE_LOCAL_HTTP=1` дозволений лише локально. У публічному середовищі він має бути відсутній. Без секретів застосунок не стартує.

## Як влаштовано облік

- Оля: початкові 4 500 PLN на 31.07.2026. Марко: 2 860,40 PLN перед початком виписки. Початкові кошти не є доходом.
- `import.py` читає Олю з `statement.csv` та `ola-*.csv`, Марка — з `marko-*.csv`. Повтори прибираються лише в межах власника. Формати мають відповідати наданим випискам; файли-доповнення повинні утворювати послідовну історію залишків.
- Марко має CSV із `;`, десятковою комою і новими операціями зверху. Рядки читаються знизу вгору, дата обліку — дата проведення банком. Рядки одного дня не пересортовуються.
- Правила містяться тільки в `rules.csv`, перше відповідне правило перемагає. Кафе й доставка об’єднані, продукти окремо.
- Фіксовані витрати Марка: Orange (телефон та інтернет), PGE, Zdrofit, YouTube Premium; решта — змінні. Колонка `фіксована-для` в `rules.csv` визначає власника для тега `#fixed`, незалежно від категорії. Allegro та Super-Pharm залишені без категорії, бо призначення покупки невідоме; сайт показує нагадування.
- Ручні операції зберігаються в `instance/manual.sqlite3`, окремо від імпорту. `FINANCE_STORAGE` задає інший абсолютний приватний каталог; у production тримайте його поза checkout і static.
- Похідні `ola-manual.beancount`, `marko-manual.beancount` та повні `ola.beancount`, `marko.beancount` відновлюються з SQLite й CSV при запуску/імпорті. Не редагуйте їх вручну.
- `main.beancount` включає банківські та ручні операції Олі; в корені створюються похідні копії цих файлів. Повний облік Марка — у приватному каталозі.
- Готівка проводиться як витрата проти `Assets:Готівка`. Початкової готівки й її надходжень не вигадуємо. Від’ємна технічна сума відображає записані списання, фактичний залишок невідомий і не показується.
- Готівкові записи форми — змінні витрати. Подвійне надсилання форми не створює повтор; імпорт їх не видаляє. Зберігайте тут саме готівкові покупки, які не будуть повторно враховані як карткові.
- Заощадження = дохід − усі витрати; Savings Rate = заощадження / дохід × 100%. За нульового доходу — «—». Від’ємні заощадження зберігаються. Банківське покриття — 01.08–15.10.2026, без прогнозування; готівка враховується за календарним місяцем.

Додаткові команди:

```bash
uv run bean-check main.beancount
uv run python report.py
uv run fava main.beancount -p 5050
uv run python -m unittest discover -s tests -v
uv run python backup.py /private/path/backup-2026-10-25.sqlite3
```

`report.html` — приватний локальний звіт Олі. Fava — лише локальний інструмент; публічно його не підключаємо. Вебзастосунок не віддає CSV, базу, Beancount-файли або report.html.

## Безкоштовна публікація на PythonAnywhere

1. Створіть акаунт PythonAnywhere Free та GitHub-репозиторій. Не додавайте фінансові файли чи секрети. Перед push перевірте `git status` і `git diff --cached`.
2. У консолі PythonAnywhere клонуйте код, оберіть системний образ із Python 3.12, встановіть uv і виконайте `uv sync --locked`. Якщо образ або мережеві обмеження не дозволяють встановлення, не переходьте на платний тариф автоматично: спочатку перевірте сумісність і повідомте власника.
3. Приватно завантажте обидві виписки. Задайте `FINANCE_STORAGE=/home/USERNAME/finance-private` поза репозиторієм. Не видаляйте цей каталог під час оновлення коду.
4. У приватному файлі `/home/USERNAME/finance-env.json` з правами `600` збережіть JSON-об’єкт зі змінними `SECRET_KEY`, `OLA_PASSWORD_HASH`, `MARKO_PASSWORD_HASH`, `FINANCE_STORAGE`, `FINANCE_HOSTS`. Значення `FINANCE_HOSTS` — точний hostname застосунку. Не задавайте `FINANCE_LOCAL_HTTP`.
5. Секрети мають надходити і до WSGI, і до консольних команд. Не покладайтеся на export в іншій консолі. Для консолі використайте `uv run python env_run.py /home/USERNAME/finance-env.json python verify.py --baseline`. Цей wrapper завантажує приватний файл у середовище процесу; його вміст не друкується.
6. У Web створіть Manual configuration, Python 3.12. Virtualenv — абсолютний шлях до `.venv` проєкту. У конфігурації WSGI до імпорту `wsgi` додайте:

```python
import json
import os
import sys
with open('/home/USERNAME/finance-env.json') as source:
    os.environ.update(json.load(source))
sys.path.insert(0, '/home/USERNAME/my-finance')
from wsgi import application
```

7. У Static files налаштовуйте тільки `/static/` → папка `static/`. Корінь проєкту, `data/`, `instance/` та приватний каталог **ніколи** не публікуйте як static.
8. Стандартний піддомен має HTTPS. Увімкніть Force HTTPS. Перевірте, що HTTP перенаправляє на HTTPS, немає циклу редиректів і застосунок бачить HTTPS. Не довіряйте довільним `X-Forwarded-*`; схему визначає WSGI хостингу. Debug вимкнений.
9. Перевірте анонімний доступ до звітів, прямих файлів і URL; потім увійдіть обома логінами, відкрийте обидва звіти, додайте тестову готівкову витрату до тестової копії бази та перевірте її після Reload і повторного імпорту. Пройдіть цей сценарій на телефоні.
10. Перевірте expiry у Web: дата має бути пізнішою за **09.11.2026**. На Free застосунок потребує продовження приблизно щомісяця; нові акаунти не мають планувальника. Перевірте доступність ще раз 8–9 листопада. Безкоштовний тариф не гарантує безперервної роботи провайдера.

Актуальні обмеження: https://help.pythonanywhere.com/pages/FreeAccountsFeatures/ . Платних API, власного домену й платної бази даних не потрібно. Деплой і перевірка на реальному телефоні ще не виконані.

## Резервні копії та відновлення

Перед оновленням створіть SQLite-копію командою `backup.py`; окремо зберігайте джерельні CSV, правила й конфігурацію. Копії містять фінанси, не кладіть їх у GitHub або static. Відновлення: зупиніть застосунок, збережіть поточну базу окремо, замініть `FINANCE_STORAGE/manual.sqlite3` перевіреною копією, виконайте імпорт із тими ж змінними середовища і `verify.py --baseline`, після цього Reload. Похідні файли відновляться з SQLite. Після повної звірки з умовою запускайте також команду без `--baseline`.
